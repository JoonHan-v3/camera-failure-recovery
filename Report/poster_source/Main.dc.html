Camera Failure and Recovery in Three Camera-Only 3D Detectors
A camera stream can go dark; when it returns, a temporal detector may still carry features built from the damaged inputs. After a front-camera outage, how quickly does detection recover, and how much does the answer depend on the model's temporal history?
150 validation scenes · 6,019 samples
3 outage durations · 9 model–duration conditions
No retraining · bit-exact repeatable runs

One outage schedule for every model
Same start for every duration and every model. Images in the half-open window [t_start, t_start + d) are replaced by black before resize and normalisation; every consumed image is audited (black counts 168 / 326 / 635).
Method
Region. Objects within 50 m in CAM_FRONT's view; 2 m one-to-one matching on a single ego ground plane.
Operating point. One score threshold per model, calibrated on pilot training scenes, never tuned on validation.
Loss. L = Rclean − Routage on the same eligible objects, per 0.5 s bin after restoration.
Event rules (frozen). Damaged if L > 0.05 with ≥ 5 objects; recovery onset = first bin with L ≤ 0.05 whose next bin also qualifies.
Memory. Models run as released: temporal state restarts at each scene start (state-isolation checks), and nothing is reset or masked when the camera goes black, so recovery reflects each model's own memory.
Uncertainty. Paired complete-scene bootstrap, B = 10,000, one shared resample for all models and durations.
Checks. Independent table rebuild (64,350 cells per model), a run-integrity gate, bit-exact reproduction of a pilot outage.

Takeaways, limits and next steps
Takeaways.
• A 0.5–2 s front-camera outage costs every model 9–22 points of front-region recall; StreamPETR loses least, BEVFormer most.
• Pooled recall is back inside the 0.05 margin from the first restored bin, except SparseBEV and StreamPETR at 0.0 s after 2 s outages.
• What lingers is a minority of objects (2–21 % of continuing objects stay missed) and a precision drop for StreamPETR and SparseBEV, not pooled recall.
• The cost sits in the outage itself, which suggests fallback cameras or blank-input handling matter more than waiting for memory to recover (an implication, not a tested claim).
Limits. A black image is an idealized failure; three complete systems differ, so architecture is not isolated; recall at a fixed threshold ignores box quality; per-event counts are small and often censored.
Next. Frozen frames and other cameras; memory reset or masking on blank input; sub-second recovery with sweeps; a second dataset.
Data and models: nuScenes (Caesar et al., CVPR 2020) · BEVFormer (Li et al., ECCV 2022) · StreamPETR (Wang et al., ICCV 2023) · SparseBEV (Liu et al., ICCV 2023). Released checkpoints, no retraining.
Read with care. A descriptive comparison of complete released systems: clean recall, thresholds, resolution, pretraining, query count and history all differ. Pilot calibration scenes may have been seen in training; intervals cover scene sampling only.
