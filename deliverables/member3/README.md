## Methodology
The procedure, in the order it was carried out. Details are in the numbered sections below.

1. **Freeze the inputs.**
   * Model: the released SparseBEV R50 checkpoint (`r50_nuimg_704x256`), no retraining, code `d341052` unmodified, mmdet3d v1.0.0rc6
     (`MODELS.md`, `artifacts/ckpt_records.json`).
   * Scenes: the full nuScenes validation set (150 scenes, 6,019 samples) and the 10 pilot training scenes shared by all members.
   * Info files: built by the upstream converter and SparseBEV's own sweep-info generator, restricted to those scenes (`build_infos.py`).
   * Hashes: checkpoint, config, info files, outage code and CUDA extension are recorded in every `run.json` / `ckpt_records.json`.
2. **Use the shared outage definition.** Member 2's frozen schedules and corruption, audit and state code, copied byte-identical, so all three
   models see one physical outage.
   * Start: t_start = CAM_FRONT sensor timestamp of keyframe 6; durations 0.5 / 1 / 2 s; half-open window `[t_start, t_start+d)` in integer µs.
   * Effect: every CAM_FRONT image in the window becomes black; the other five cameras are never touched.
3. **Confirm what the real loader consumes** (§3). The replicated manifest from the inventory is replaced by execution of the real loader
   code: history = 7 previous *keyframes*, zero camera sweeps, online and offline paths identical.
4. **Inject the outage on raw pixels.** `OutageFrontCamera` runs right after `LoadMultiViewImageFromFiles`, before resize/crop, GPU
   normalization and the backbone. Because only the current six images are decoded in single-GPU mode and history comes from a cache of
   features, the black frame also stays black as history (§3).
5. **Control the model's state** (§4). SparseBEV has no recurrent state but a filename-keyed feature cache: it is cleared at every run, and
   a guard rejects any frame whose own features are already cached; each condition is a separate process (batch 1, no workers).
6. **Run the matrix.** On each split 5 runs: clean twice, then 0.5 / 1 / 2 s. fp32, TF32 off, deterministic. All native decoded boxes kept
   in the common prediction format; every consumed image is audited.
7. **Verify the inputs independently of the model** (§6): audits against raw-JSON recomputation, CPU and GPU-hook probes of the tensors the
   backbone receives, unit tests.
8. **Verify the model's behaviour** (§6): clean twice bit-identical, prefix identical, isolation with negative controls, and the
   **finite-window check** (the plan's temporal-contamination test for finite-window models).
9. **Pass the baseline gate** declared before the result (|ΔNDS| ≤ 0.010 vs 0.556) and score all runs with the official nuScenes evaluation.
10. **Build and verify the front-region evaluator** (§5): projection from raw tables checked against the devkit; matching, ignored GT, empty
    bins, threshold selection and recovery confirmation tested on controlled examples; per-sample counts re-implemented independently.
    Rules and the calibration threshold are frozen on the pilot scenes **before** any validation event statistic is computed
    (`artifacts/provenance/EVENT_RULES_DECLARATION.txt`).
11. **Produce per-scene statistics for all three models** with the same evaluator: per scene, per phase (pre, during, bins 0.0–4.5 s),
    clean and outage on the same eligible objects. This also cross-checks Members 1/2: their missing-bin scene counts (14/26/34) are
    reproduced by an independent implementation of the bin rule. Bootstrap and curves are Member 4's.

## 3. Adapter and execution path (verified on the pinned code)
* Test pipeline: `LoadMultiViewImageFromFiles(to_float32=False)` → **`OutageFrontCamera`** → `LoadMultiViewImageFromMultiSweeps(test_mode)` →
  `RandomTransformImage` (resize/crop to 256x704) → format; GPU side: BGR→RGB, mean/std, pad /32, GridMask (identity in eval), backbone.
* Timestamps: upstream `get_data_info` provides `img_timestamp` as float seconds and the model uses it (`time_diff` in
  `sparsebev_transformer.py`), so it is **not** replaced; the adapter runs with `ts_mode='abs_s'` (`round(t·1e6)` equals the integer µs of the info —
  asserted for every frame). The runner adds only `scene_token` and `eval_ts_us`.
* Real loader selection (`confirm_loader_manifest.py`, executed): history = 7 previous keyframes of the same scene; val 288,912 slots, 36,114 unique
  keyframe files, 0 sweeps; online ≡ offline selection. Single-GPU mode decodes only the six current images (≈ 6 JPEG reads/sample) and takes
  history features from `SparseBEV.memory`, so a black frame's cached features stay "black" as history by construction.
* Iteration: dataset order = timestamp order; scenes verified contiguous; one process, no workers, batch 1; `SceneStateGuard` rejects any
  revisited scene / non-increasing timestamp. (`collect_sweeps` indexes `data_infos[index-1]`; contiguity of scenes keeps that inside the scene.)

## 4. Model state (the filename-keyed feature cache)
* Upstream never clears `memory` between runs; features are looked up by filename, so a cache left by an outage run would be reused
  by a later clean run on the same files. Measured in `isolation_pilot.json` (stale-cache control).
* The runner clears `memory`/`queue` before every **run** (verified through `reset_between_runs`); it does **not** physically empty the cache at
  each scene boundary — entries of the previous scene stay until the FIFO evicts them, but they are keyed by other filenames and never read (scene
  history is disjoint; alone-vs-continuous equality in §6.5 shows no effect). Before every frame the runner observes the real cache: the frame's own
  filename must **not** be cached (else `StateResetError`) and the 7 history entries must be served from the cache (or be the frame itself at a scene
  start). `run.json` records `never_cached_before_own_frame`, `history_served_from_cache_after_first_frame` and, per scene start, the boolean
  "own frame not cached" (`model_state_fresh_at_scene_starts`) — this is the observed condition, **not** an observation that the whole cache is empty.
* No other temporal state exists, hence the **finite-window test** (§6.7): predictions must equal the clean run exactly once no
  black frame is inside the 8-keyframe window.

## 5. Custom evaluator (projection, matching, thresholds, recovery) — `outage/evaluator.py`, frozen in `EVENT_RULES_DECLARATION.txt`
* **Geometry** (`gt_tables.py`, raw JSON): LiDAR(sample time) → global → ego(CAM_FRONT time) → camera; clean calibration, sample-time
  annotations, camera-time ego pose, no motion compensation to exposure time (documented approximation). Region = depth > 0, inside the original
  1600x900 image, ground-plane distance ≤ 50 m from the sample-time ego origin. It indicates projected centre location, not guaranteed visibility.
* **Eligible GT**: ten detection classes (devkit mapping) in the region with ≥ 1 annotated LiDAR or radar point.
* **Ground plane (geometry v2)**: ONE explicit frame — the sample-time **ego** frame (LIDAR_TOP-keyframe ego pose) — for the 50 m region rule *and* for
  matching; matching distances are the XY norm between the **geometric centres** (prediction z_bottom + h/2, GT gravity centre) after transforming both
  from the LiDAR frame into the ego frame (`gt_tables.ground_xy`; `match_sample` takes these coordinates explicitly). Geometry v1 measured matching in
  the LiDAR sensor's XY plane (prediction z = box bottom), which is tilted ~2.6° w.r.t. the ego plane; the Inspector found one real TP/FP assignment
  that crossed the 2 m boundary because of it. v1 records are preserved in `artifacts/superseded_geometry_v1/`; `artifacts/geometry_regression.json`
  reproduces the example (sample `8c394cbb…`, row 23: LiDAR-XY 2.0266 m → FP; ego plane 1.9997 m → TP; counts TP/FP 3/1 → 4/0) and lists the affected
  counts for every model/condition (≤ 21 of 6,019 samples per run; calibrated thresholds unchanged).
* **Matching** (per sample): class-aware, one-to-one, ego-plane centre distance ≤ 2 m (inclusive), predictions by descending score
  (ties: input order), nearest unmatched eligible GT (ties: lowest index); then ignored same-class GT (any same-class GT that is not eligible)
  absorbs the prediction; remaining unmatched predictions are FP **only if their own centre is in the region**. Greedy descending-score matching
  makes the threshold-τ result equal to the matching of the prefix {score ≥ τ} (tested), so one pass serves every τ.
  `ign` counts all predictions absorbed by ignored GT over the whole 360° (mostly outside the region); it is not part of precision.
* **Threshold** (per model, pilot clean predictions, frozen before validation): maximise pooled precision TP/(TP+FP) with recall ≥ 0.30 and ≥ 100
  region predictions; undefined precision never wins; ties → higher recall → lower τ. Achieved precision/recall and native score floors are reported
  (`artifacts/calibration/`), since the procedure does not equalise operating points across models.
* **Damage / recovery** (functions `damaged`, `recovery_onset`, tested): loss L = R_clean − R_outage on the same eligible objects; damaged iff
  pooled L during the outage > 0.05 with ≥ 5 eligible objects; onset = first post-restoration bin with L ≤ 0.05 whose next *adjacent* scheduled
  bin also has L ≤ 0.05 (both with ≥ 5 objects); a missing/insufficient bin breaks the pair; the last bin can never be an onset.
* **Per-scene statistics** (`event_stats.py`): per scene, per phase — `pre` (front keyframe before t_start), `during` (front keyframe in the
  window = the image the model consumed was black), `b0.0 … b4.5` (post-restoration bins, one-to-one assignment with the **same convention as
  `audit.missing_bins`**, evaluation-time offset, ±0.25 s), `other` — counts of eligible GT, TP, FP, ignored and region predictions for the clean
  and the outage run. A sample whose camera frame was black but whose evaluation time is already ≥ restoration (≤ 43 ms camera lead) is counted both
  in `during` and in its bin. Same-object join: `per_sample_<tag>.pkl["per_sample"][condition][sample]` holds `score`, `status`, `gt_idx` and `matched_instance`, aligned with the
  predictions in descending-score order; `gt_idx` indexes the **full** `gt_<split>.pkl[sample]['gt']['instance']` list and `matched_instance` gives the token for
  TP rows directly. The pickle's `eligible_gt_instances` is a filtered denominator list, **not** aligned with `gt_idx`.

## 7. Causality, timing and limitations
* Causal policy = Member 2's frozen alignment allowance (image ts ≤ sample ts + 50 ms). SparseBEV consumes only camera images (no CAN bus, no
  future frames); the observed skew is −46.1 ms … +1.9 ms on the pilot (all keyframes ≤ +49.99 ms over trainval). The 7 history keyframes are earlier samples.
  No zero-latency claim is made; transport/processing delay is unmeasured.
* The released model was trained on the train split; pilot/calibration scenes were seen in training (all three models); the nuImages pretraining overlap
  with val cannot be excluded.
* Environment deviations: torch 1.9 + meshgrid shim, cudnn.benchmark False, own info generation (`MODELS.md` §2); the baseline gate is the check.
* Native decoding keeps ≤ 300 rows with score > 0.05 (val mean 215; one val sample has no prediction at all, handled as an empty bin by the evaluator; BEVFormer/StreamPETR keep 300 without a floor); thresholds calibrated here are far above 0.05, so the
  event analysis is unaffected, but "all-queries" comparisons across models are not available for SparseBEV.
* Missing follow-up bins come from the shared schedule/keyframe spacing (14/26/34 scenes for every model); reported, never hidden; they break only the
  adjacent recovery pair that contains them.
* Latency in `run.json` is synchronized per-frame end-to-end time including JPEG decode with two concurrent processes and no warm-up discarded — not the
  isolated warmed-up batch-one latency (Member 4).
* Each GPU process holds ≈ 4.4 GB (2.65 GB peak allocated + CUDA context/cache): at most two run at once on the 12 GB card shared with the desktop
  (three, or two started simultaneously, hit CUDA OOM; failed runs leave no `preds.pkl` and are retried by `run_worker.sh`; logs of the first failed
  attempt: `artifacts/logs/failed_oom_first_attempt/`).
* Sampled checks: the independent per-sample re-implementation was run on all 402 pilot samples and on 1,204 evenly spaced validation samples; the devkit
  projection check on 4,513 boxes in 150 samples.
